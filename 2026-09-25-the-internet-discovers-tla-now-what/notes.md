## 随文选主例子的独立复核

从[交互页](https://reasonable.io/figures/tla-playground)提取公开的 `Election` 规格，在临时目录原样运行：正常三节点配置完成检查，得到 38 个不同状态；允许重复投票后，TLC 给出六次动作的反例。

反例中，节点 1、2 先各自参选，节点 3 依次向两者投票。于是 `{1, 3}` 和 `{2, 3}` 都被计作多数，两名候选者先后成为 leader。多数集合相交，必须配合每个节点的投票约束，才能支持这个例子的唯一性论证。

模型允许选主完成后没有后续动作。首次使用默认配置时，TLC 在这样的终止状态报告死锁。为单独核对文中的安全不变量，这两组记录明确使用 `CHECK_DEADLOCK FALSE`；这不是无死锁结论。重复投票配置发现反例后即停止，其 57 个已发现状态也不是完整状态空间的统计。[完整记录](examples/publisher-checks.json)

## 1. 安全性通过，究竟排除了什么

实验检查的 `Safety` 有两个部分：变量取值属于声明的集合；如果任务已经完成，那么它必须启动过。这两个条件限定了某些不允许出现的状态，并没有要求系统必须离开初始状态。

把 `AllowStart` 改成 `FALSE` 后，TLC 只发现一个状态，安全条件依然通过。这不是检查器犯错，而是“不得提前完成”与“最终必须完成”本来就不同。一个根本不完成的任务，没有违反前一项要求。

因此，阅读验证结果时应把性质名称展开。例如，“检查 Safety 通过”在这里只意味着这两个具体条件通过，不能把名称里的 Safety 理解成系统在所有意义上都安全。

## 2. 活性反例包含一个无限尾部

没有公平性时，TLC 实际给出的反例为：

```text
ready，started = FALSE
  → running，started = TRUE
  → 永远停顿在 running
```

前两项是有限前缀，最后一项表示无限延续的行为。不是再多跑几个普通步骤就能把这个反例排除；规格本身允许系统一直不选择 `Finish`。

加入弱公平性后，运行中持续启用的 `Finish` 不能永远不执行。同样，初始状态中持续启用的 `Start` 也不能被无限拖延。允许的状态没有变多，所接受的无限行为变少了。

而当启动动作的条件始终为假时，对 `Start` 要求公平性不会创造一次启动机会。`BlockedProgress.cfg` 仍得到反例，具体输出见 [results.json](examples/results.json)。这提醒我们把动作能否启用和启用后是否获得执行机会分开。

## 3. 公平性是在声明什么环境前提

可以再构造一个未实现为本地模型的逻辑示意：任务只有在窗口打开时才能执行，但环境反复打开、关闭窗口，始终不给任务执行机会。

窗口不断开关时，执行动作并没有持续启用，弱公平性不一定排除这条行为；如果执行机会出现无限多次，强公平性才进一步要求动作不能一直错过机会。这个比较依据的是动作的启用方式，不是把“更强”当作一律更好的选项。

用于真实系统时，应说明谁负责兑现前提：调度器是否会让线程运行，网络重试是否真的有成功机会，外部服务是否可能永久不可用。把公平性加进规格，会改变定理的前提；它没有修改生产环境，也不会修复使动作永远不可执行的条件。

## 4. 可达状态不变式不一定直接支持归纳步骤

这是本轮实验中最值得多看一遍的区别。

正常初始条件下，`Safety` 在所有可达状态成立。但下面这个状态也满足 `Safety`：

```text
phase = "running"
started = FALSE
```

它满足类型约束，也满足“完成则已经启动”，因为当前并没有完成。然而，从它执行一次 `Finish` 会得到 `phase = "done"`、`started = FALSE`，违反 `Safety`。

这个起点在正常模型中不可达。检查从真实 `Init` 出发的可达状态，不会遇到它；直接尝试证明 `Safety /\ Next => Safety'`，却必须考虑它。

`NotInductive.cfg` 有意把所有满足 `Safety` 的状态都作为初始状态，TLC 找到了上述两状态反例。日志中的 6 个不同状态是发现反例时的统计，运行此时已经停止，不能将其当成完整遍历的状态空间大小。

我们于是增加一个更强条件：

```tla
InductiveSafety == TypeOK /\ (started = (phase # "ready"))
```

它排除了“运行中却从未启动”的状态。一个手工归纳说明是：初始状态满足它；`Start` 同时改变阶段和标志；`Finish` 保留已经为真的标志；`Wait` 不改变任何变量。它也蕴含原来的 `Safety`。

`Strengthened.cfg` 检查了这个有限状态模型的保持性并通过。这里的手工论证没有交给 TLAPS 或 Verus；TLC 的结果也不等同于一个对任意规模程序成立的机器检查归纳证明。

## 5. 精化需要连接行为，而不只是复制函数名字

下面是用于理解精化的自编任务分解。设实现的详细状态是 `c`，抽象模型状态是 `a`，映射 `alpha(c)` 把实现状态解释成抽象状态。

首先需要检查初始对应关系：实现的合法起点映射后，应满足模型的初始条件。其次检查一步对应关系：实现的一步执行，映射后要对应模型允许的变化，或对应抽象层观察不到的停顿。

例如，真实任务启动可能涉及写数据库、发队列消息和等待消费者。把这三个实现步骤都简单标成一个抽象 `Start`，并没有证明对应关系。还需要处理部分成功、重试、消息重复和崩溃后的恢复状态。

涉及活性时还会出现另一个缺口：实现能否永远做内部工作，但映射后一直停在同一个抽象状态？即使每个实现步骤分别满足安全的对应关系，这种无限内部停顿仍可能妨碍进展。因此还要讨论终止、调度与公平性条件如何对应。这一段是理解问题的分析框架，不是完整的精化证明规则。

## 6. 机器检查通过，还要看证明了哪条命题

Verus 官方教程解释，`assume` 会把条件作为未经证明的事实交给求解器，矛盾假设能够使任意结论得到“证明”。其面向 LLM 的指南还讨论了规格被修改、函数体跳过检查等问题，并建议核对生成前后的变化。[assert 与 assume](https://verus-lang.github.io/verus/guide/requires_ensures.html)、[LLM 证明指南](https://verus-lang.github.io/verus/guide/llmforverusproof.html)

据此，本次阅读提出四个分别需要回答的问题：

| 环节 | 应当核对的对应关系 |
| --- | --- |
| 原始需求到形式规格 | 规格是否表达了真正需要的行为与异常情况 |
| 一种规格语言到另一种 | 翻译是否保留了状态、动作与性质的含义 |
| 证明生成 | 命题是否保持不变，是否引入未经证明的假设 |
| 抽象模型到实现 | 实际执行是否满足模型及环境前提 |

第二个模型复核第一个模型的翻译，可以作为工程审查，但不能仅凭两者意见一致，就认定获得了语义保持证明。即使翻译后的命题被严格证明，翻译本身也仍是需要说明的一环。

## 7. LTL、CTL 与 ATL：先辨认量词

补充论文把线性时间逻辑、分支时间逻辑与交替时间逻辑的差别，放在路径量化和策略选择上讨论。[Alur、Henzinger、Kupferman，2002](https://www.cis.upenn.edu/~alur/Jacm02.pdf)

用本次状态图作一个独立比较：

- “每条允许的行为最终完成”，会被永远停顿的行为否定。
- “从每个可达状态都存在一条通向完成的路径”，在允许启动的图中可以成立，即使仍有永远停顿的路径。
- “某个参与者有办法确保完成”，还必须规定它能控制哪些选择，以及其他参与者能否阻止它。

这三句话分别在问必然性、可能性和策略能力。看到多个 agent 出现在系统里，不足以决定必须采用哪一种逻辑；应先说明希望表达的性质和谁能控制哪些动作。

## 8. 本轮阅读形成的判断

我会把重点放在两个连接处：从自然语言要求到形式命题，以及从抽象状态到实际实现。一个证明生成器在已固定的命题上表现良好，很有价值，但仍需要交代这两个连接处的依据。

对后续研究结果，最想进一步核对的是翻译支持的语言范围、采用的公平性前提、证明依赖与未经检查的部分，以及哪些结果确实连接到可执行实现。评测任务、规格／性质对、证明文件和软件实现是不同的计数单位，不能互相替代。

## 9. 补充研究：Verus 的规格、证明与实现

2026-09-27 补充了[独立专题](verus-study.md)，将原文的语言统一观点落实成三个可验证程序：限幅函数、非零元素计数、配额状态更新。它们分别演示函数契约、归纳与循环不变量，以及抽象状态到字段修改的对应关系。

实际验证中，规格的数学加法与执行代码的机器整数加法差别尤其直观：配额条件在数学上可以写成 `used + amount <= limit`，但照抄到执行分支可能在判断前溢出。把实现改为先比较 `amount <= limit - used`，再结合状态不变量，验证器才有依据证明加法安全。

三个程序均通过验证、编译和运行；五种错误变体按预期被拒绝。[实验与结果](examples/verus/README.md)记录了版本、诊断和验证范围。这是另行编写的基础实验，没有复现 Reasonable 的 TLA+ 到 Verus 流水线。
