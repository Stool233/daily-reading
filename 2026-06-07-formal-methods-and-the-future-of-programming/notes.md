# 阅读笔记

## 一句话总结

Agentic coding 让形式化方法从“理论上很强但工程成本太高”变成“可能成为 AI 编程时代核心验证与反馈基础设施”的候选方案。

## 关键概念

- **形式化方法的成本收益曲线**：过去成本太高、适用面太窄；agent 降低使用成本，生成代码又增加验证需求，使投入重新变得合理。
- **验证瓶颈**：模型生成代码越来越容易，但判断这些代码是否能进生产仍需要大量人类 review。
- **证明作为反馈**：证明失败、规格不满足、类型错误，都能给 agent 提供比自然语言批注更精确的修正信号。
- **全称保证**：类型系统或证明技术可以排除一整类坏状态，而测试只能覆盖样例。
- **语言与证明共设计**：为了让证明技术真正工程化，可能需要同时调整编程语言、类型系统和证明工具。
- **内部试验场**：Jane Street 的工程文化让高级类型系统和语言实验有真实用户，这对形式化方法落地很关键。

## 文章主张

1. Jane Street 过去对形式化方法谨慎，主要是因为完整验证成本太高。
2. Agentic coding 改变了局面：模型能帮助写证明，也让验证生成代码变得更重要。
3. 形式化方法不只是安全关键系统的专用工具，未来可能像高级类型系统一样成为日常软件工程工具。
4. 测试、property-based testing 和 fuzzing 是必要的，但它们无法完全解决状态空间覆盖问题。
5. 类型系统已经证明了机器可检查反馈对 agent 编程的价值，更强证明技术值得继续探索。
6. Jane Street 的优势不是比外部社区更懂所有证明工具，而是能把语言设计、证明方法和真实生产使用结合起来。

## 值得记住的数据点

- 文章用 seL4 作为形式化验证成本的代表案例：25 人年验证 8,700 行 C。
- seL4 的经验中，证明文本规模约为实现代码的 23 倍，每行代码约需半个人日验证。
- Jane Street 对形式化方法的新目标，是让它像今天的高级类型系统一样，成为构建软件时普遍有用的工具。

## 我的理解

这篇文章最重要的转折点不是“AI 能自动证明程序正确”，而是“AI 改变了谁能使用证明工具，以及证明工具为谁提供价值”。

过去形式化方法的典型使用场景，是少数专家在少数极高风险系统上投入大量时间。这个模式很难推广到普通生产软件。Agent 出现后，证明不一定马上变得便宜，但写证明、调证明和理解证明系统的操作成本可能显著下降。原本需要专家手写的许多技术细节，可以由模型辅助完成。

同时，AI 编程放大了验证问题。代码生成变快后，瓶颈自然移动到“怎么知道这些代码是对的”。如果 review 仍主要靠人读代码和跑测试，生成速度越快，review 压力越大。形式化规格、类型约束和证明义务有机会成为新的中间层：人负责定义正确性边界，机器负责持续检查，agent 负责根据反馈修复。

Jane Street 的判断也很符合他们的背景。他们不是从零开始相信形式化方法，而是从类型系统的实际收益外推。对他们来说，高级类型系统已经是“形式化方法可工程化”的证据；现在的问题是，能不能把这个经验扩展到更强的证明技术。

## 对 agent 工程的启发

- 给 coding agent 接入类型检查、测试和 lint 只是第一步；更高阶的反馈可能来自规格、模型检查和证明义务。
- Agent 写代码时，应该鼓励它同时产出或更新规格，而不是只产出实现和测试。
- 对关键模块，可以把 review 重点从“逐行读实现”转向“确认规格是否表达了真正的不变量”。
- 语言和框架设计会影响 agent 能否被有效约束；可验证性可能成为未来语言特性的竞争点。
- 证明工具如果要进入日常工程，需要和 CI、编辑器、代码审查、自动修复循环紧密结合。

## 可延伸思考

- 对普通业务系统，最小可行的形式化方法是什么：更强类型、状态机规格、TLA+、Dafny、Lean，还是局部契约检查？
- Agent 能否自动从现有测试和事故复盘中提出候选不变量？
- 证明失败应该如何呈现给 coding agent，才能比传统编译错误更有用？
- 哪些代码最值得优先形式化：并发、权限、账务、交易、协议，还是数据迁移？
- 如果证明由 agent 生成，人类 review 应该审证明本身，还是审规格与不变量？
- 形式化方法会不会成为 AI 生成代码的“质量闸门”，类似今天很多团队对类型检查和测试的依赖？

## 待补充问题

- Jane Street 这支形式化方法团队会优先选择哪个证明工具或自研方向？
- OxCaml 会在类型系统中加入哪些与 ownership、mutability 或 specification 相关的新能力？
- 形式化方法如何与现有 OCaml 代码库渐进集成，而不是要求重写？
- 对 agentic coding 来说，证明技术的收益会主要体现在训练阶段，还是日常编码阶段？
